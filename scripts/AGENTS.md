# 构建与运行入口规范

- 使用上游 QEMU 的 configure/Meson/Ninja 构建；只保留固定依赖获取、集成与明确运行所需的薄入口。
- 源码依赖固定上游 tag/commit，构建和运行输出放 `work/`；输入镜像只读，输出不覆盖既有证据。
- 维护入口使用简短单词文件名，例如 `build.sh`、`run.py`、`devices.py`；不使用连字符或冗长下划线名。重命名同步更新当前调用者，不留旧路径兼容入口。
- 不重写下载器、任务调度器、版本系统或模拟器控制框架；优先使用 Git、QEMU CLI、QMP 和 GDB。
- 记录实际命令、版本、退出码及运行范围，不把局部诊断称为机身启动。
- 临时 GDB 命令、单次断点脚本、地址检查 helper 和调试操作说明放在忽略的 `work/debug/`，不提交机器本地配置、日志或 socket。版本库只维护稳定的构建、运行入口和合成夹具；设备行为与实际研究结论写入 `docs/`。
