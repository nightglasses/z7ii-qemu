# Contribution workflow

- Public articles follow the [documentation standards](docs/writing.md). Task links belong in contribution metadata; the handbook explains technical subjects and evidence.
- Scheduling issues live in mashiro01/nightglass. PRs here reference the full issue URL; do not create duplicate task ledgers.
- Use isolated branches/worktrees with explicit ownership. Do not undo collaborators' changes. The parent owns scheduling, focused validation, pushes and PRs. Merge reviewed, locally validated changes promptly without waiting for CI; preserve commit history.
- Start each task from the current integration baseline on codex/<feature>, one reviewable goal per branch. State dependency baselines, delete integrated task branches and do not use old feature branches as the mainline.
- Commit implementation, tests and contract documentation for one capability together. Consolidate local documentation corrections for the same conclusion; keep independent devices/protocols in separate commits. Raw disassembly, debugging and experiments stay ignored; reviewed, self-contained evidence summaries may be published under the documentation archive policy.
- Check the complete diff, applicable native validation and git status before committing; deliver a clean tree. Rewrite only explicitly authorized local history, first preserving original refs and uncommitted work. Never rewrite published mainline or others' active worktrees.
- Reuse upstream QEMU CPU, MemoryRegion, IRQ, clocks, loader, GDB and trace APIs. New code expresses only bounded, deterministic, evidenced Nikon board wiring/device contracts. Functional CMOS, readout, services, graphics, IRQ and scanout are the goal; missing physical-camera evidence, exact Bayer fidelity or complete GPU precision does not block functional implementation. Functional acceptance and physical fidelity are separate claims.
- The root qemu/ pinned official submodule is the sole upstream dependency; keep its tracked content clean. Nikon sources under hw/nikon, include/hw/nikon and tests/*/nikon belong to this repository. CMake rejects upstream modifications or Nikon directories inside the dependency; generated integration stays in ignored build directories.
- Choose the smallest complete implementation. Do not add generic schedulers, compatibility entry points or a second emulation framework.
- Assistant shell commands use rtk. Product code invokes explicit tools directly and must not depend on the local token filter.
- Use ordinary Git refs and direct content comparisons. Do not introduce research-pipeline hash fields, calculations or gates.
- Report original execution, hypothesis execution, complete boot and reconstruction comparisons separately. Do not inject guest events/state to force success, invoke guest callbacks/ISRs, alter PC/task state or prefill/fix/host-render UI pixels. Bounded device state machines, DMA, IRQ and scanout producing actual modeled results are legitimate device behavior.
- Deliver meaningful small synthetic fixtures and one applicable batch. Do not repeat full validation without a new change or unresolved failure.
- Merge fixed commits promptly after independent review and applicable build; delete merged task branches and retain ignored raw execution evidence.
