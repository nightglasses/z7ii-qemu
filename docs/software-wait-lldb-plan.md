`scripts/observe-software-wait.lldb` is a native LLDB command file, loaded into a fresh target after connecting to the stopped upstream QEMU GDB stub. It creates seven named, one-shot **hardware** breakpoints, requires hardware support, and never launches, connects or initially continues a process. No Python callback, new runner, guest function call, register/memory write, firmware instruction replacement or single-step is used. Assignments are only to explicitly declared LLDB convenience variables. Command expressions forbid JIT fallback; conditions contain only scalar registers, those convenience values and one bounded source-derived current-cell read. Each native command list stops on error and ends in `continue`; there is no unconditional auto-continue which could hide failed reads. Missing register support or evaluation errors must remain stopped and be recorded as an observation limitation.

The marker requires the already observed ordinary LR104000C1, index4 and tableB185E020. It reads live `MPIDR_EL1` and the matching current cell atB2B415F4+4*prid, enabling the first generic `make_wait` for that exact non-null TCB. Both Cortex-A7 affinity slots are0/1 in pinned upstream source; the command refuses values outside those slots and does not equate debugger thread numbers with CPU affinity. Pinned ARM `gdbstub.c` exports dynamic CP registers and `helper.c` defines `MPIDR_EL1`; the remote register's actual availability remains to be verified at connection. A null current pointer produces no guessed TCB read or fallback target.

Any source-derived dynamic pointer read that fails stops the observer rather than widening memory or substituting zero.
