# Four finite I²C interfaces and the next original data dependency

This stage implements the four original controller bases `2c018000..2c01b000` and guest IRQs214..217 for [the original MAS startup work](https://github.com/mashiro01/nightglass/issues/331). The original initializer's IDR write `2c018028=2ff` is interrupt masking, not FIFO acknowledgement. Original geometry, configuration, request/cancel and distinct ISR variants are recorded in [the fixed whole-protocol research](https://github.com/mashiro01/nightglass/blob/2f11242/research/z7ii/qemu-i2c-contract.md). Its1160B original-byte candidate coverage is distinct from complete accepted native CFG coverage; only the initializer had previously been dynamically observed.

The virtual board starts each controller idle: CR/address/count/ISR/pause/timeout0, IMR2ff, empty16-byte TX/RX FIFOs and independent nominal48MHz Clock. These are functional assumptions, not Nikon reset or rate measurements. Word-only MMIO follows the [Linux v6.12 Cadence register interface](https://github.com/torvalds/linux/blob/v6.12/drivers/i2c/busses/i2c-cadence.c#L21-L118) and the AMD register/protocol references linked in the research. SR derives bus/FIFO/direction state; IER/IDR change one mask, and ISR events persist until W1C. Reads do not create transfer completion.

Each controller owns an official [I2CBus](https://github.com/qemu/qemu/blob/4fc49f46dc95d4a27de2509e7fceb2931e91faeb/hw/i2c/core.c#L106-L182), Fifo8, Clock and virtual-time timer. An address request schedules actual upstream start/send/recv/end actions; an empty bus returns address NACK. Byte frames use9 virtual SCL cycles and the candidate divisor22×(divA+1)×(divB+1). No peripheral is attached in the original machine. The positive synthetic test alone attaches upstream `at24c-eeprom`; its bytes are not camera data.

Normal7-bit master TX/RX is supported. TX TRANS_SIZE returns unsent-byte-count minus one (empty0); RX TRANS_SIZE is remaining expected bytes, and slave counts describe queued FIFO state. These are the standard candidate conventions, not proof of Nikon's variant encoding. RX full waits for guest pop/rearm rather than dropping data. Empty DATA read reports RXUNF and returns a named underflow value0; full DATA write reports TXOVF and preserves existing bytes. FIFO clear cancels work and clears counts/FIFOs; W1C remains separate. HOLD retains a selected endpoint, permits same-address repeated START and stops when released after completion. Configured TX starvation timeout is `(TIMEOUT+1)` virtual SCL cycles; zero disables that assumption. No external slave master is invented.

Unbound operations fail: original CR bit7 extension, monitor-mode ADDR requests,10-bit master addressing, changed endpoint during a held transaction, unsupported widths/offsets and illegal active configuration changes. CR SLVMON can be stored as configuration, but the original master+monitor combination cannot silently become an ordinary transfer. Idle slave configuration does not implement an external slave-controller endpoint. State migration/snapshots are explicitly blocked with upstream unmigratable VMState.

The next independent dependency is the original external record scanner over `[12e00000,12e40000)`. Its absent payload backing and empty/ENDM semantics require a separate finite storage profile; they are not an I²C response or a valid factory-data result.

Review found two transaction-boundary defects in the initial implementation: releasing HOLD during a pending address phase could report COMP without executing upstream START; changing TIMEOUT while an acknowledged empty TX was waiting could leave the previous deadline armed. C `2d070f1f1919c0f2efb18d468b2c1624f57a19fc` fixes both generically. HOLD release retains pending-address work; only an addressed, completed TX may complete directly. Mutable waiting timeout deletes the old timer and reschedules from the current virtual instant, or stays waiting when disabled. Failed address selection must still produce the real NACK.

That exact C built incrementally with exit0 and passed18 focused checks in `work/issue331/i2c-state-2d070f1/result.json`: the original15 plus pending-HOLD-release/empty-bus NACK, acknowledged timeout disable/re-enable, and replacement of an old deadline by a longer one. The latter two use an official EEPROM only in the fixture, observe real DATA after ACK, and wait past the old deadline without TIMEOUT/STOP before testing a newly armed deadline. No unchanged original run was repeated or relabeled. The binary includes the separately documented finite record aperture; these18 checks concern I²C and do not establish record parsing or original application transfer success.
