# Original polling USIO transmit interface

This stage continues [QEMU: recover IRQ timer RTOS and interprocessor startup dependencies](https://github.com/mashiro01/nightglass/issues/331). The [fixed whole original UART contract](https://github.com/mashiro01/nightglass/blob/4c021e5/research/z7ii/qemu-rtos-startup-contract.md) joins original initial-task callback `O294` to `O180`, channel0/base `2c090000`. It writes byte SCR0/UPCL80, SMR1, ESCR0, SSR.REC80; halfword FCR0, BGR363, FCRc and optional405; finally it reads SCR and sets TXE. Original polling TX reads SSR.TDRE before writing halfword DR; the alternate path preserves the nine-bit DR field. The new model implements this whole observed register/width/phase interface, not a 16550 alias.

The independent [Socionext authored USIO header](https://github.com/killsmm/m10v_mono/blob/cebff0686425b739bf63e87c911591ab30b03c1a/ca7_rtos/target/cpu_tkernel/basefw/MILB_API/MILB_Header/include/Peri/_jmiluart.h) and [Linux v6.6 driver](https://github.com/torvalds/linux/blob/ffc253263a1375a65fa6c9f62a893e9767fbebfa/drivers/tty/serial/milbeaut_usio.c) support the offset/width and named-bit match. Linux defines FCR.FE1/FE2/FCL1/FCL2/FDRQ at bits0/1/2/3/10 and the divisor as clock/baud−1. Original405 contains transmit FIFO enable/flush/request, but no FTIE/FRIIE. No UART IRQ number or receive producer is established here; the supported profile does not create UART IRQs or received characters.

Virtual-board assumptions are explicit: reset configuration is zero/disabled with empty TX holding storage; UPCL and FIFO flush actions self-clear, cancel pending output and leave empty TX. The virtual UART clock is an independent nominal100MHz, not inferred from the counter's48MHz. BGR363 corresponds to divisor868; a modeled8N1 frame occupies8680 virtual clock cycles. The one-word TX holding capacity models only this polling path, not physical FIFO depth. DR accepts nine bits and preserves all nine for the original RMW readback; the host character stream observes the low eight bits. SMR1/ESCR0, SCR0/1/80/81, REC80, FCR0/c/405 and BGR363 are the implemented functional profiles. Other fields, widths, offsets, baud/IRQ/receive modes and writes while TX is occupied fail explicitly.

TDRE is produced by actual holding-empty state. A guest DR store marks it occupied and schedules an upstream virtual timer; only timer expiry plus consumption by the upstream CharFrontend backend makes it empty. Backend backpressure retains occupancy and retries at a virtual frame interval. With `-serial none`, the declared disconnected transmitter finishes at the same frame deadline without inventing input. With `-serial file:...` or a supported QEMU character backend, it delivers real output. It uses [upstream CharFrontend nonblocking write](https://github.com/qemu/qemu/blob/4fc49f46dc95d4a27de2509e7fceb2931e91faeb/include/chardev/char-fe.h#L220-L232), official Clock conversion and QEMU virtual timers; no host guest-memory writes or handler calls. Migration/snapshots are rejected until serialization is implemented.

Incremental native build exited zero. Eight focused synthetic checks passed in `work/issue331/usio-first/result.json`: complete original initialization/readback, TDRE occupied→timer completion with real file output `A`, pending-output UPCL cancellation with no emitted byte, disabled TX, unsupported baud/IRQ profile, word width and register hole rejection. Deterministic icount gives a deadline long enough to observe occupied TX before completion; these small test bytes are not recovered firmware. The unchanged original image is run separately; these fixtures do not prove physical UART timing, menu input, scanout or whole-camera boot.
