# SLA staged configuration

## Original source contract

Provider: `zero-domain-source/work/sla-whole-source-11/sla.S` and its original
`sla-rows.jsonl`, complete `10093DC0..10094320` family. This audit uses the
published original instructions and literal bindings; no new decoding, inferred
function roots or runtime qualification is claimed. The first cfd SLA runtime
failure was CPU3 `PC10093E48`, W32 `20202018=0`, within the recovered stop method.

Reuse `TYPE_NIKON_STAGED_CONFIGURATION`: MMIO0 at `20202000`, size `254`, aligned
little-endian word accesses, one IRQ output. `10093E0E` registers object `14E`,
`C1001278`, then IRQ `123` with handler `10093DC1`. Unlike a software-only
callback registration, this handler reads the mapped pending register and
acknowledges it. The SLA machine owner supplies private mapping and IRQ wiring.
All three named `external-event` inputs remain disconnected by default.

`10093E26` starts and `10093E3C` stops through E8 lock/request wrappers
`10094302` and `100942E2`, writing `+18=1` or `0` between them. IRQ enable is a
separate `10093E52` method. The wrappers call `67196/67210/67248/67198`; they
are separate E8 service operations, not extra registers in this aperture.
The `67196/67198` service slots are literally `BX LR` in this source; the
lock-wrapper terminology does not imply physical locking or extra MMIO.

ISR `93DC0` reads `+2C`, then writes that same word to acknowledge its causes.
It reads mode `+200`. In nonzero mode, pending bit1 consults request `+08` and
cancels once that request reads zero; in zero mode, pending bit16 cancels.
Pending bit2 always cancels, writes `+18=0`, and restores mask `+20` from the
software object's `+4`. An optional callback in object `+8` receives event
`41050401` and a pointer to the saved pending word. The physical producer and
its timing are not identified by this consumer body.

## Functional model and validation

No production C change is required: the existing mature model covers the entire
source contract. Its cold zero state, applied configuration readback, atomic
`+10` staging, cancellation, and explicit rising-edge event provider are
functional conventions already documented in `protocol.md`, not new physical
claims. The provider maps requests `08/14/0C` to pending `2/4/10000`; an armed
request completes only on its explicitly supplied event. Neither configuration
writes nor elapsed virtual time produce completion. Pending state survives
masking, cancellation and disable until W1C acknowledgment or reset. The IRQ
output is gated by enable and the pending/mask intersection.

The new standalone helper `nikon_staging_test(QTestState *, const char *,
uint64_t)` in `tests/qtest/nikon/staging.c` is intended for the SLA owner's fresh
VM fixture at `/machine/sla/staging`, `20202000`. It covers the exact cold stop,
all source configuration fields and both coefficient loops, publication only at
commit, unbracketed setters, retained optional parameters, all three explicit
providers, selective and same-word W1C, interrupt masking, cancellation, no
spontaneous completion and reset with a held external level. The sole builder
compiled and executed the focused private-SLA case with exit0 in1.30s;
its ignored receipt is `work/slastagingnativereceipt.log`. It establishes this
functional contract, not a recovered physical producer or original completion.
