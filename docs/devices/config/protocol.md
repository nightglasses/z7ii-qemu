# MXIC configuration snapshot and slot transaction

The current complete transaction, selective publication, dual completion IRQ and live parameter contract is [interrupts.md](interrupts.md). It supersedes the completeness and open-access restrictions in the historical first-profile receipts below. Earlier runs and test results retain their original scope; they are not claims about the current binary.

This layer continues [QEMU startup and device contracts](https://github.com/mashiro01/nightglass/issues/331). The [fixed original-byte contract](https://github.com/mashiro01/nightglass/blob/5b2db90/research/z7ii/qemu-mxic-region-contract.md) supersedes the earlier manual final-address list from revisions `a01d4d6/9b4c29f` and recovers 926 bytes / 341 native instructions: the original active snapshot, subsequent draft writes, slot request and independent parameter writes. It does not establish Nikon silicon identity or physical reset values.

The original snapshot selects `TRVSW=1` at candidate PA `20010044`, reads nineteen configuration words and 512 slot words at `20014800`, then selects zero. The virtual board starts with zero configuration/slots and idle `TCFLG=1`; this is a declared functional preloader state. The guest produces its own snapshot in RAM. TAEN gates table accesses; a valid `TCFTRG=1` request publishes selected retained draft portions after a modeled 10 μs. Snapshot writeback cannot set availability. The complete later SLA producers prove partial writes and closed TAEN at submission; the old complete-write restriction is removed. A real completion latches TMIF bit0, gated by TMIE and acknowledged by W1C.

This protocol has primary manufacturer-source counterparts, with explicit layout differences: [_jdsmxic.h](https://github.com/killsmm/m10v_mono/blob/cebff0686425b739bf63e87c911591ab30b03c1a/ca7_rtos/target/cpu_tkernel/basefw/MILB_API/MILB_Header/include/Image/_jdsmxic.h) lines 93–224 defines request/status, view, access and acceptance fields. [im_mxic.c](https://github.com/killsmm/m10v_mono/blob/cebff0686425b739bf63e87c911591ab30b03c1a/ca7_rtos/target/cpu_tkernel/basefw/MILB_API/Project/ImageMacro/src/im_mxic.c) lines 906–995 separates table access from configuration processing; lines 9573–9589 defines internal-circuit reads under `TRVSW`. The PC-debug branch that forces ready is not used. The published table definition gives seven-bit slot bytes, matching the modeled 512-word table. Nikon's `+5004/+5020` parameter group has no exact vendor field binding; its recovered word interfaces are kept as full-width configuration state, without assigning physical master names.

Four routing words, thirty-six TLVL words and thirteen source-qualified TRMC word-zero parameters have independent live state. They are not held for a second slot request: both original MAS and SLA write TLVL/TRMC after slot completion without another request. Candidate TLVL masks are `3f3f030f/003f3f03/003f3f03`; TRMC mode bits 1:0 and period bits 27:16 give mask `0fff0003`, matching the manufacturer header's `io_mxic_trmcw` / `io_mxic_trmcr` field formats. Nikon's layout differs from the manufacturer's array bases, so this counterpart establishes candidate fields without exposing its entire register window. These states do not simulate bandwidth arbitration or physical performance. The thirty-two boolean words at `20016a00..20016a7c` remain owned by the separate MXIC device, with virtual zero reset and guest programming.

The pre-slot initialization also writes four finite live selector banks starting at `20013000`, stride `100`: twenty-three words at `+00..58` and eight at `+bc..d8` in each bank. All 620 recovered values across the five source configurations fit candidate `TMARLP` port/level fields, mask `33`, defined by the manufacturer header lines 442–461. The model retains those two fields per selector; it assigns no physical master ID to a bank or slot. Holes `+5c..b8` stay unsupported. Three additional focused fixtures exercise all 124 selector writes/readback and reject a hole and an invalid field, with results in `work/issue331/mxic-config-selectors-first/result.json`. These three ran against C revision `66a2cf6c378c8ac86d990d45cfc9cfa23ae7eaa7`; they are distinct from the earlier ten-fixture result. A separate reset fixture on that same binary verifies that applied active state is cleared and the second guest entry independently completes a new transaction; `work/issue331/mxic-config-reset-first/result.json` does not claim to test reset during a pending request.

The current complete SLA source `1076d278`, `sla.S` function `100538b0` and capture entry `10053b18`, confirms the same nineteen-word / 512-slot transaction and all four selector and boolean banks. The selector passed in r0 selects an eleven-word row: `11 * r0` computes the row index, row word zero points to the live selector/level configuration, and the next ten words supply TRMC parameters. The final literal bases are PA `20012648`, `20012490`, `20012790`; source arithmetic produces twelve independent write destinations because two row parameters each have two consumers. The actual CPU2 write `PC10053afc / PA20012638=00300002` is one member of that full row, followed by `20012640` and `200127a8` elsewhere in the same producer. The MAS contract also programs `20012618`, giving thirteen distinct words in their union.

`config.c` now decodes this complete union as six finite groups by base, count and stride: `2490` count2 stride10; `2618` count2 stride10; `2638` count3 stride8; `2658` count2 stride8; `2790` count2 stride8; `27a8` count2 stride8 (hex offsets relative to CONFIG PA `20010000`). Each word accepts the defined mode/period fields, without a list of accepted profile values. The nineteen transaction fields likewise use four groups with counts 2/8/1/8. Every other offset, including the previously disproven `24a8`, the intervening word-one locations and group holes, retains `MEMTX_ERROR`. No manufacturer array range is guessed into Nikon's map.

Capture `10053b18` selects active view, reads all nineteen words and 512 slots, restores draft view and branches to its full initializer. This is one valid producer shape; later owned source `1005A354` provides the sparse form. Both use the same selective retained-draft transaction and genuine completion timer. Reads and snapshot writeback cannot set completion; live writes during pending and active-view writes remain rejected.
