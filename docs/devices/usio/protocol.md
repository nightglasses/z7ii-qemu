# USIO asynchronous UART and FIFO profile

The device implements the asynchronous UART register family instead of the old initial-task-only transmit values. The original initial task initializes channel0 at PA `2c090000` with byte SMR/SCR/ESCR/SSR and halfword DR/BGR/FCR transactions. The unchanged original GUI run in `run gui/original` reached GUI phases1/2 and message-task execution, then rejected CPU0 `PC103bc668 WRITE8 PA2c09000f=2`. That transaction addresses the high byte of FBYTE, the receive-FIFO threshold interface. This is an observed failure of the preceding polling-only model; it is not a successful run of this revision.

Register names and masks are qualified by the [fixed Socionext2015 header](https://github.com/killsmm/m10v_mono/blob/cebff0686425b739bf63e87c911591ab30b03c1a/ca7_rtos/target/cpu_tkernel/basefw/MILB_API/MILB_Header/include/Peri/_jmiluart.h) and [fixed Linux6.6 `milbeaut_usio.c`](https://github.com/torvalds/linux/blob/ffc253263a1375a65fa6c9f62a893e9767fbebfa/drivers/tty/serial/milbeaut_usio.c). The saved Linux driver is named `milbeaut_usio.c`, not `fujitsu_usio.c`. The matching [FM0+ Communication Part peripheral manual](https://www.infineon.com/assets/row/public/documents/30/44/infineon-fm0-family-peripheral-manual-communication-part-usermanual-en.pdf?fileId=8ac78c8c7d0d8da4017d0f9148df7ea0), UART pages53–76, supplies a declared functional macro profile for FIFO pointer, idle and request semantics. These references do not identify the Nikon chip, transfer another board's base addresses or establish Nikon interrupt numbers.

| Offset | Register | Access and behavior |
|---|---|---|
| `0` | SMR | byte; SOE, bit direction, stop length and asynchronous MD0/1 configuration |
| `1` | SCR | byte; TX/RX enable, TX/RX interrupt gates, self-clearing UPCL |
| `2` | ESCR | byte; 5/6/7/8/9 data bits, parity/inversion/flow configuration |
| `3` | SSR | byte; live TBI/TDRE/RDRF, real input error latches, REC clears errors |
| `4..5` | DR | halfword or individual byte lanes; nine-bit data, low-byte/halfword TX commit and RX dequeue |
| `6..7` | BGR | halfword or individual byte lanes; arbitrary15-bit internal divider |
| `c..d` | FCR | halfword or individual byte lanes; FIFO role/enable/flush, retransmit controls, FIFO interrupt gates/request |
| `e..f` | FBYTE | halfword or individual byte lanes; reads live FIFO1/2 occupancy, writes RX interrupt thresholds |

The `8..b` hole, 32-bit accesses, reserved fields, CSIO modes, BGR.EXT without an external clock and diagnostic FIFO test bits remain explicit errors. Natural halfword and byte lane writes merge existing register state, so guest read/modify/write sequences retain other lanes. DR high-byte writes stage the ninth bit; a subsequent low-byte or halfword write enqueues the data. Empty RX reads return the last DR latch, including the original nine-bit TX read/modify/write use; they do not create a receive event.

Two upstream Fifo32 queues hold real TX/RX data. Declared capacity is128 words for5–8-bit frames and64 words for9-bit frames, following the matching128-byte macro profile and Linux's128-byte FIFOs. Disabled FIFOs use a one-word holding capacity and preserve stored data. FSEL exchanges FIFO1/2 TX/RX roles only while both enables are clear and no transfer/data remains. FCL1/2 clear the corresponding queue; functional TX flush also cancels its in-flight frame. Flush/reset actions self-clear. UPCL cancels both directions and errors. This cancellation behavior and zero/disabled reset configuration are board assumptions, not measured reset timing.

TBI requires both an empty TX queue and an empty shifter. TDRE requires an empty transmit holding/FIFO queue; an enabled FIFO can still accept data while TDRE is zero until its bounded capacity is reached. A DR transaction fills storage; TX enable moves a word into the shifter and schedules an upstream virtual timer. Only its frame deadline and backend acceptance complete that word. Backpressure retains the word and retries at a frame interval. With no backend, the transmitter shifts out at the same deadline and produces no received bytes. With a backend it delivers real low-eight-bit character output. The host stream represents logical characters; parity, inversion, bit direction and the ninth bit are retained as guest configuration/data and timing, without pretending the byte backend exposes physical line encoding.

FDRQ is a hardware empty-transition latch. A software one cannot assert it; software zero clears it. FTIE gates this actual latch. FSET saves the empty TX FIFO's write position; later guest writes populate bounded retained storage. FLD reloads that retained sequence with TX/FIFO disabled, without regenerating invented bytes. FLSTE enables FLST when subsequent writes overwrite retained data. Lost retained data cannot be retransmitted. FSET and FIFO reset clear loss state; FSET/FLD pulse bits read zero. The model uses bounded retained storage rather than guest-memory manipulation.

CharFrontend receive callbacks are the only normal RX producer. They require RXE and available capacity; received bytes populate the RX queue and excess input latches ORE. A real backend break supplies a zero character plus FRE and disables the selected receive FIFO according to the declared macro profile. REC clears these error latches. FBYTE writes select thresholds; zero during Linux initialization is normalized to one when used. RDRF arises from actual queued data reaching that threshold. FRIIE additionally permits below-threshold data to set RDRF after eight baud clocks of actual receive idle. Reset/flush cancels the idle deadline. Byte-stream delivery into RX is immediate at the callback; the idle event is timed. No software message, HCI command, GUI phase or missing peer synthesizes RX.

The independent nominal100MHz Clock is an explicit virtual-board input. BGR uses Linux's `clock / baud - 1` relation. Frame timing includes start, configured data bits, optional parity and one/two stop bits; it is not a fixed BGR363 or8N1-only rule. Physical oscillator source, accurate bit sampling, line faults and silicon reset timing remain unverified. FLWEN requires real chardev modem CTS input through the upstream serial ioctl; an unsupported/disconnected modem input is not assumed asserted. An external clock is not fabricated.

The two SysBus IRQ outputs are RX at index0 and TX at index1. They follow RXE/RIE plus receive/error state, and TXE plus TBIE/TIE or FTIE plus transmit state. No IRQ is raised merely for elapsed host time or desired guest continuation. Linux platform IRQ numbers are not used. The source-qualified three-instance machine contract below attaches independent `serial_hd(channel)` frontends. An absent backend remains disconnected. Migration remains rejected until FIFO/timer/retained-state serialization is implemented.

The saved GUI source's indexed projection has16 typed USIO address references, all on channel0; it does not establish the absence of computed references to other channels. The exact native row at `103bc668` is `STRB r0,[r1,#f]` and has no accepted function owner. Its saved neighboring rows program threshold2, SCR.RXE, FCR.FRIIE and FCR.FE2. Before that sequence, `r0=ba` calls the complete `10103f18` API, which computes the GIC distributor bit and stores to ICENABLER at `+180`. This establishes an interrupt186 disable call. The sequence does not set SCR.RIE.

Pure indexed followup of SVC6 registration API `10104510`, then its dynamic wrapper `103a051a`, reaches the complete original UART initializer `10202ce2`. It registers interrupts186–191 using six original Thumb pointer literals at `10202f5c..70`. The exact veneers pass logical channels0/1/2 and branch to common TX/RX paths. Odd interrupt handlers branch to complete owner `10202bee`, which consumes the real guest TX queue through `10202b84` DR writes. Even handlers branch to saved native rows at `10202c56`, which read SSR receive errors, apply REC, clear SCR.RIE and notify the RX side. The original software uses three structures at `b18064a4 + 58 * channel`. Their field `+8` supplies the MMIO offset added to UART register bases. The established original COPY0 producer copies ROM O`[2379f94,2428d4c)` to RAM `b1800000`. A direct264-byte original payload read at O`2380438` covers all three88-byte structures. Their first fields are ID116/channel0/offset0/opaque8480, ID117/channel1/offset10/opaque8581, and ID118/channel2/offset20/opaque8682 (hex words). Thus the physical offsets are original initialized data produced by the guest loader, not an inference from IRQ order or host preinitialization. The opaque `+c` fields are retained as source facts without assigning unproved hardware meaning. The ignored read receipt is `run usio/namespace.json`.

The board creates three independent devices and names them as explicit machine QOM children `usio0`, `usio1`, `usio2`; each has a16-byte aperture and the same byte/halfword protocol. It connects SysBus IRQ0 to the corresponding RX GIC input and IRQ1 to TX. Do not allocate UART memory beyond this source-qualified three-slot namespace. The source projections are saved candidate facts from producer `ec048f9fde8723ba2db9657f2e88410933b21099`, not accepted source roots or a new native execution. The six veneers and common RX rows remain unowned in the saved function inventory; their exact native rows and qualified literal entries are preserved without inventing function extents.
