# Stream requests, parameter capture and processing storage

C1.70 MAS starts paired work before its upstream graph can deliver pixels.
Request admission is therefore separate from data processing and completion.
The finite model admits both paired banks and all42 configured graph ports,
retains genuinely pending requests and supplies three source-declared RAM pools.
It also corrects the earlier type0 model: publishing parameters does not create
permanent processing ownership. No frame, result, raw event or guest callback
is generated by these admissions. Actual RAW consumption, numerical work and
result publication are defined separately by the [pixel operator](pixels.md).
The execution receipts below preserve the earlier admission-only checkpoint.

Code, ROM and software-object addresses below are original MAS virtual addresses
(VA); device and named pool ranges are board physical addresses (PA). Addresses,
MMIO offsets and masks are hexadecimal. Counts, dimensions and explicitly
identified software byte offsets are decimal. Ranges exclude their upper end;
device words are aligned little-endian32-bit. The
[receipt](/evidence/imagerequest/requests.json) separates source, conventions,
fixtures and original execution.

## Paired admission and the original software notification

`10369faa` writes selected-bank `10=1`, then `08=1`. Repeated-work worker

waiting for hardware results. The current request is `42190803`, callback

Each bank independently follows these finite states:

| Input | Required state | New state | Effect |
| --- | --- | --- | --- |
| `10=1` | Quiescent | Armed | Retain one request |
| `08=1` | Armed | Awaiting input | Await actual data work |
| `0c=1` | Awaiting input | Drain pending | Await real work/result completion |
| Whole-device reset | Any | Quiescent | Cancel without completion |

Helper `10369fc4` establishes the finish address precisely: literal
`203800ec` minus `e0` is `2038000c`. It is not offset `14`, which remains
unsupported. Offset `0c` retains its existing value1 configuration convention
outside active work. Query `10369f98` and consumer `102e531a` distinguish
zero from nonzero at bank+`18`; the model returns a virtual boolean, zero in
quiescent/armed and one while awaiting input/drain. Physical status bits and
latency are not recovered.

Unarmed `08`, duplicate initial arming and malformed starts reject without
changing state. A running `10` kick follows the [pixel continuation contract](pixels.md#work-completion-and-cancellation).
Configuration and time cannot produce a frame. Final result `118`, real work
drain and the aggregate cancellation requests `54/60/6c/78` now follow the
[pixel lifecycle](pixels.md#work-completion-and-cancellation). Cancellation
does not publish an image completion.

First configure/start `102e4f5a` and repeated work `102e4724` use different
waits. The latter waits `110`, then requests finish and waits `120`; its
first-phase event10 has software producer `102c056c ->102e5498/102e54a0`.
That event must not be replaced with a hardware completion. IRQ99/100 handlers
`103699a4/10369968` consume raw pending at+`24` through existing W1C and callback
routing. Raw progress classes and numerical result production remain separate.

## All graph-node requests and parameter reload

`103b4cea ->103bd07c` writes backend+`0=1` for configured processing nodes,
in reverse graph order. Every one of the42 known ports now admits that request
only after successful import, with reset deasserted and no outstanding start.
The finite readback is0 before request and1 afterward. The original status
predicate `103bdbbe` checks `(word &3) !=3`; no successful result is invented.
Local reset cancels only that node's request and imported configuration;
whole-device reset clears all requests. Neither produces pixels or events.

The separate [type0 capture contract](../gate/slots.md) atomically installs
thirteen staged words at selector2c. Configuration-only worker
`103b4e1e(a2=4)` calls the graph configurator and returns `421930e4` without
starting a processor. Normal execution later reloads an already allocated
slot in this configuration-only path. This falsifies the old busy-on-publication
hypothesis, rather than proving a missing pixel-completion event.

Committed parameters, CPU staging and active-frame ownership are separate.
Quiescent full reloads are accepted; partial reloads preserve the old snapshot.
When any graph node is requested, availability queries and further publication
remain explicit unsupported active-use boundaries. The model does not pretend
such a request is idle or mutate a frame's unknown consumed parameters.
There is no busy-clear timer, software-resource release or frame retirement.

### Numerical interpretation and physical limits

Actual arithmetic need not wait for silicon precision. Configuration item21
(software pointer-array byte offset84), through VA `102e57a6`, supplies two
matrices. Setter `1036bb78` packs nine13-bit A coefficients at PA
`20380b00..20380b10`, with a separate15-bit control in the first word. Setter
`1036beaa` packs nine signed12-bit B coefficients at `20380b64..20380b74`;
the first coefficient is sign-extended into its whole word. The current A has
diagonal1024. Current B's row sums are512/0/0; another original initializer at
VA `1040e77e` uses the standard RGB-to-luma/chroma coefficient pattern. These
facts support Q10 A and Q9 B as finite numerical interpretations. Rounding,
saturation,12-to8-bit normalization and chroma centering remain model choices.
Applying these guest coefficients is preferable to hardcoded neutral chroma.

The input connection follows the existing capture-work engine after it
successfully writes every packed RAW row. The paired operator consumes
that completed DMA buffer and its generation, rather than the scene provider or an
earlier acquisition acknowledgment. Matching its PA against `310..31c` selects
one phase; all grid/main/reference addresses must use that same phase. The
repeated0/1/0/1 addresses are aliases, not four independent outputs to overwrite
at once. Freshness, reset/configuration cancellation and output backpressure
precede every result event.

NV12 main output is a candidate, supported by geometry and the same
`09000201` slot packet in an existing Z7 software experiment. That experiment
explicitly assumes its encoding and skips enabled calibration, so it is not a
verified C1.70 operator. The next discriminating evidence is downstream Y/UV
read extent, subsampling and order. Likewise the proposed two-plane LE16
reference format needs its next-frame and any independent consumer checked.
The [finite operator](pixels.md) implements explicit defect filtering,
spatial/temporal kernels and precision, without claiming recovered table
equations. Its external calibration tuple restricts every opaque configuration
field; unsupported table/control combinations reject without publication.

## Historical admission validation and unchanged execution

The old model fails four focused regressions: paired status readback, configured
graph-node start, DMA from the missing kind25 pool and legal parameter reload.
After the corrections, the applicable native batch passes35 memory and23 SLA
subtests. It exercises both paired banks, all42 ports, all sixteen parameter
slots, atomic full/partial reload, active-use rejection, every new pool unit,
cross-page DMA, exact edges and reset. Time alone never produces a result or
completion. These are synthetic device fixtures.

The unchanged60-host-second continuation uses bounded NOR resource35 via
descriptor17, cold-neutral resource80, a quadrant PGM, paced healthy9600-baud
UART, RNG0, acceleration(0,0,1024), held F4 and five-CPU MTTCG. It imports18
packets/649 words and performs nine parameter captures; valid mask `13e`
selects slots1/2/3/4/5/8. Slots3/4/5 are legally reloaded through the
configuration-only path. All graph nodes are inactive at the snapshot;
paired bank0 awaits input, bank1 is quiescent, with no raw pending.
This crosses the old start and permanent-busy boundaries without completing
the still-unmodeled image operator.

That checkpoint completes128 main acquisitions and507 statistics jobs, with
no rejection, one main cancellation and no statistics cancellation. Its first
uncovered transaction is CPU0 VA PC `106ee3c6`, WRITE32 PA `201810e0=1`,
reporting `transfer-stream-truncated`. Subsequent diagnostics capture complete
664/1032-byte graphics streams; this length error is not evidence of missing
source bytes. Later graphics continuation belongs to the
[startup frontier](../../validation/frontier.md).

GUI readiness remains zero. Both1124-byte image-information records are equal
and contain173 nonzero bytes, with leading word1 and geometry word `02aa0400`
(1024×682). Head1
binds a1024×682 console showing status widgets and a memory-card error overlay;
head0 is unbound. Later diagnostic-only runs do not reproduce that binding,
so stable first-enable timing remains unverified. There is no GDB pause inside
the observation window. Subsequent QMP
and read-only GDB reads are sequential rather than atomic or physical rates.
The earlier busy-on-publication receipts remain historical model observations;
they do not establish physical frame ownership. Normal GUI startup, numerical
paired processing and frame retirement remain unverified.
