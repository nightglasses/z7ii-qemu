# Dual Audio I/F and per-beat HDMAC requests

This stage addresses [QEMU 原版启动与最小设备模型](https://github.com/mashiro01/nightglass/issues/331). Code `180d7e49f0b934cda8ad16c0a7964e84e7af3aed` adds the two-channel Audio I/F at `2c080000` and GPIO request inputs on the existing HDMAC. It keeps original instructions, task dispatch, IRQ handlers and data transfers in the guest.

## Source and model contract

The frozen [whole Audio contract](https://github.com/mashiro01/nightglass/blob/142a5a3/research/z7ii/qemu-audio-contract.md) derives two 52-byte guest objects, two channel blocks at `+100/+200`, GIC IRQ167/168, the original initialization and runtime register families. Its 3846 bytes/1550 instructions have partial historical native coverage, explicitly reported there; uncovered bounded original-byte methods are not claimed to have complete native CFG acceptance. The manufacturer-authored [Socionext Audio header](https://github.com/killsmm/m10v_mono/blob/cebff0686425b739bf63e87c911591ab30b03c1a/ca7_rtos/target/cpu_tkernel/basefw/MILB_API/MILB_Header/include/Peri/_audio_if.h) supplies compatible fields and FIFO geometry, with different base/channel count. This is an IP protocol hypothesis, not a Nikon silicon identity.

The named virtual profile has zero configuration/reset word, disabled channels, empty FIFOs, no errors and an independent nominal 48MHz Clock. AURES bits0/1 assert/reset only the selected channel; release supplies no samples. The original AUCR12/13 enable-command variant is supported directly. AUCR full/empty and AUST usage flags derive from real queue occupancy. Underflow arises from an enabled internal output clock attempting to consume an empty FIFO; its flag is W0C, so writing1 preserves it and writing0 clears it. IRQ167/168 depend on enabled cause bits. Unknown widths, bank holes and extension registers fail.

The sink consumes **opaque 32-bit words**, without PCM playback or inferred low-half left/right packing. Combined data uses one queue; separate PIO uses two opaque lane queues and consumes a pair only when both are present. Capacity is1 or16 selected stages. Original format encodings44/4d and0a/0c can be latched as opaque profile labels;4d is not assigned a physical bit depth. Original unknown AUMD bits23/26 are retained explicitly. Swap/loopback, nonzero AUDP routing/packing, separate-lane DMA and AUDMA2 sample-count modes remain unsupported. Disconnected input never reports full or fabricates samples; an attempted empty input read fails. AUCC divider-enabled output advances from virtual time using the documented divisor candidates; without an internal clock source it waits. These assumptions do not measure hardware rates or EXPEED performance.

The module reuses pinned QEMU [Fifo32](https://github.com/qemu/qemu/blob/4fc49f46dc95d4a27de2509e7fceb2931e91faeb/include/qemu/fifo32.h), Clock, QEMUTimer, IRQ/GPIO and [DMA bus helpers](https://github.com/qemu/qemu/blob/4fc49f46dc95d4a27de2509e7fceb2931e91faeb/include/system/dma.h). It deliberately uses a declared virtual sink rather than guessing a codec/PCM backend. Stateful devices remain explicitly unmigratable.

Original Audio logical DMA IDs132..139 select HDMAC bank1; real guest configuration selects the channel. Audio output channels connect selectors3/7, disconnected input selector5 remains low. HDMAC external requests accept one real bus beat per timer action, then recheck the live request. Full output FIFO deasserts DREQ and pauses the channel with EB set and no SS5/CI. The sink frees a stage and resumes it. Every bus callback checks operation generation/running state, preserving reset/cancel during synchronous bus reentry. The final actually accepted beat produces completion; no host callback or event flag substitutes for guest IRQ handling. Remaining CA count fields retain the prior functional convention until completion.
