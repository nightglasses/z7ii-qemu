# Peripheral event router functional profile

The original Z7II callback registrar reads and modifies a mask at 20060034. Its whole family owns finite configuration, three raw pending/ACK domains and guest callback dispatch. The model uses the functional name `peripheral-event-router`; this does not identify a physical chip or SoC block. It lives under `hw/nikon/devices/` and is instantiated by the Z7II machine. No address-number type or compatibility alias is added.

Source contract `114f3d1e41410a176ef25bef5e9be5e5e779a39c` in TOOL's `qemu-peripheral-event-router-contract.md` preserves 1728 bytes/696 continuous diagnostic instructions, 13 saved function metadata records/276 instructions, two lane tables and the eleven callback masks. The actual registrar's separately selected source is 13 BB/100 bytes/37 instructions with zero direct frontier. Those diagnostic and saved-source scopes remain different. Original package callbacks, mutexes, registry fields and event flags remain guest RAM and guest code.

The sparse aligned32 aperture is [20060000,20060330). Configuration at 00/04 uses generated 3F fields; 08/0C uses 7FFF; 10/14/18/1C are generated booleans; 20/24 use 7FF. Mask/config words 34/40/4C retain full32 because the original setters have unclamped word inputs. Configuration at 70..9C, A0/A8/AC/B0, 314 and the six lanes' C8/CC/D0/D4/D8/DC/EC words is retained full32. The six E8 lane words, B4..C4 and 328/32C are generated bytes. A4 accepts changes to low five bits while preserving all other prior bits. Low-level index APIs have no proven dynamic bound; ownership of finite physical words is not a claim that every out-of-range packet can be detected. A4 and the value 3 at 70..9C are opaque retained configuration with no invented operating effect.

IRQ86 dispatches raw38 low11 to eleven guest callbacks. IRQ87 dispatches raw44 to two callbacks and IRQ88 dispatches raw50 to one. The machine connects these three mature SysBus IRQ outputs to GIC86/87/88. IRQ89..93 have no established producer in this family and are not added. `external-pending` qdev inputs are an explicit virtual fixture interface: pins 0..10 latch raw38 bits0..10, pins11..42 latch raw44 bits0..31 and pins43..74 latch raw50 bits0..31 on rising edges. The original run leaves every provider disconnected.

Cold configuration/pending zero, rising-edge latches and same-word W1C are named functional assumptions. Mask1 enables delivery; 34's software callback association is evidenced, while using 40/4C to filter the other two IRQs is a separate virtual convention without a physical gating proof. Mask changes recalculate lines but retain pending. Reads do not ACK or generate events. Guest writes clear only selected pending bits; the guest executes handlers and callbacks itself. Reset clears configuration and pending and preserves actual provider levels, so a held input does not become a new edge. There is no timer, DMA, frame/data producer, host callback or direct flag/task write.

Unknown requests at 28/2C/30, holes, invalid fields and unsupported widths fail before modifying prior state. A compound guest method may stage known configuration and then receive an error on its unknown request; this is not a successfully implemented whole transaction. B0's nonzero readback is its retained written value, not an independent ready source. Original callback registrar input and callback pointers are never host-filled.

Thirteen new focused fixtures are planned at the frozen implementation: source-shaped callback mask RMW, three unknown-request rejections, invalid generated fields/holes/widths/end, and three qtests covering every finite lane/config field, independent masked pending/ACK IRQs, no clock-driven event and transactional reset recovery. Build, focused and changed original results will be appended at their exact later native revision; earlier receipts remain immutable. Whole boot and menu are unverified.
