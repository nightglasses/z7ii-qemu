# Raw ARM observer ABI

The runtime observation at native revision `a5bcb8816c7d03f4e99890b0d156ec2dcc0357be` stopped before its pattern breakpoint commands with `Cannot access memory at address 0x18a`. Its error and register snapshot remain in the original receipt; no guest resume followed the error. The precise speculative memory value was not read after the failure.

Native GDB 18.1 reports `auto` ABI as APCS when configured for ARM without an ELF executable. Its pinned `arm_scan_prologue` implementation, in the absence of function symbols, reads the word at r11 and guesses a code start from that word minus eight. The same implementation returns before this heuristic when the ABI is AAPCS. Breakpoint condition setup selects the current frame before its expression-evaluation exception handler. This explains how an implicit frame read can fail before a register-only condition or its command list runs; it does not establish a guest NULL access.

The observer now explicitly selects AAPCS and prints the resulting policy. This is a debugger profile for raw register and source-bounded memory observation, not a general acceptance of a firmware ABI or inferred stack unwind. All seven hardware addresses, conditions, read scopes, permissions and asynchronous continue/interrupt behavior are unchanged. No target instruction, register, memory, event or model behavior changes. Offline native GDB parsing verifies AAPCS and the three denied inferior-write/call permissions. A subsequent observation must independently verify actual target progress and cannot retag the failed run as successful.
